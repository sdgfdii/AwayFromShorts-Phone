# 电脑版每日限额移植 · 1.58.0 / 2183

对照本次工作区的 `AwayFromShorts/src/quota-rules.ps1`、`src/game-quota.ps1`、`src/web/index.html` 及 README 中的独立／共享限额功能实现。未修改电脑版。

## 手机入口与规则

冻结应用 → 每日限额 · 独立 / 共享 → 管理每日限额。

- 可选择本机应用，一应用一格独立计时，或多个应用放一格共用额度。新增默认120分钟，可设1–1440整数分钟。相同应用不能重复放入多个格子。
- 支持修改、合并、拆分、移除、启停。合并默认取所选格子的最小上限，可在保存前调整；拆分后各应用沿用共享格子的上限，分别扣除各自实际已用时间。
- 用量按包名保存，不绑定可变格子，合并拆分和移除再加不会清空。只计启用并纳入限额后的前台时间，停用和移除期间不计；后台、锁屏、灭屏不计。补查系统事件可恢复进程停留期间的有效前台用量，本机零点重置。
- 应用、上限、分组、限额开关原先仅每天21:00–21:59可改；2026-10-30 起用户要求放开，`DailyQuotaData.EDIT_WINDOW=false` 表示随时可改，页面显示「随时可修改 · 当天已用时间保留」，控件不再禁用，Store 也不再拦截写入。把常量改回 true 就恢复旧的 21:00–21:59 窗口：判定、提示和 `nextEdit` 都还留着，不需要重写。
- 使用情况权限先放开：未授权时额度照常保存，但不计时、不冻结，授权后立即恢复计时与冻结。已授权但事件不可读、用量损坏或无法保存时保护性冻结，损坏用量的保护持续至次日。额度耗尽约每5秒检查并通过设备所有者的暂停应用能力冻结；若那只应用正好停在前台，同一节拍会主动把“今天的额度用完了”提示页拉到最前，当场结束这次使用，不必等用户退出。
- 新全天限额独立于原有 `AppUsageQuota`。原有“放进时段只计该时段、额度用尽才冻结”及旧全天额度保持原样。新限额不会改变时段规则；暂停或移除新限额也不会解除原有时段、学习联动或禁忌冻结。只有关键应用豁免学习闸门，关键应用也不能豁免每日限额，热爱奖励不能抵扣每日限额。

## 实现边界

- `DailyQuotaData`：纯数据模型，配置校验、多应用唯一分组、包级用量、水位、零点切分、固定修改窗口。
- `DailyQuotaStore`：`afs_daily_quota/config`与`usage`，在同一SharedPreferences提交中原子保存配置和当前账本。每次修改先用旧配置结算至当前时刻，再换配置，避免新应用追溯旧时间或停用期间计时。
- `DailyQuotaActivity`：跟随主题的原生设置、应用选择、独立／共享格子和剩余额度。
- `Guard`：合并时段和新限额的目标集合；原因5为每日限额耗尽，任何其他冻结仍保留。新限额应用默认参与学习闸门；关键名单可包括这些应用。
- `GuardService`：后台独立工作线程约5秒检查新限额，达到／恢复额度边界时触发统一Guard.apply；原有30秒守卫节拍保持。
- `FreezeBoardActivity`：新增独立入口、支持拖入应用，显示新限额及真实冻结原因；返回设置后刷新配置并保留页面位置。
- `LocalBackup`：本机完整备份包含新配置和用量，不包含凭据。恢复仍受原有设备管理／宽限期限制。

## 1.58.7 更新：统一限额容器和时段范围

当前入口改为“冻结应用 → 使用限额 → 管理限额 · 独立 / 共享”。不再单独显示每日限额格子。上文1.58.0中“新限额始终全天累计、不会替代自身强制时段”仅描述旧版，现已由本节规则替代。

额度跟随应用的RuleStore绑定：不在任何时段则全天累计，放入时段则只统计该时段内的前台时间。共享组可包含不同范围的应用，合计各自范围内的用量；超额仅在该应用自己的范围内冻结。时段内未超额时可以使用。暂停／移除新限额会恢复原时段强制冻结；旧AppUsageQuota、学习联动和禁忌逻辑保留。移动前结算旧范围，移动后继续同一当天账本，不清零。时段中的额度就地显示，未绑定的应用及其额度在全天容器显示并支持长按拖动。
## 1.58.12 更新：条上不留字、权限先放开、额度到点就请出去

- 冻结页的使用限额只看进度条：条上方那行「已用 x / y 分钟 · 剩余 z 分钟」去掉，读数只留在无障碍说明里；条本身可点，进管理页或旧全天额度编辑。视觉上只剩长度和颜色，一屏里多条额度不再互相抢注意力。
- 使用情况权限先放开：`FreezeBoardActivity` 的额度编辑不再拦在授权对话框后面，`DailyQuotaStore.save` 也不再因为未授权而拒绝保存。未授权时额度只是保存，不计时、不冻结（`AppUsageQuota.exceeded`、`DailyQuotaStore.exceeded` 都以授权为前提），授权后同一个节拍立刻恢复累计和冻结。已授权但事件不可读、用量损坏或写盘失败时仍保护性冻结。
- 额度用尽当场生效：`setPackagesSuspended` 只挡下一次启动，停在前台的实例照样能刷，所以 `GuardService` 的 5 秒节拍在冻结之后补一步 `Guard.kickQuotaExceeded`：用使用记录里最后一段还开着的前台区间判出当前应用，命中原因 4／5 就用设备所有者身份把 `QuotaBlockedActivity` 拉到最前。提示页显示应用名、当天用量、零点重置说明；返回键和「回到桌面」都回桌面，额度恢复后自己退场。灭屏时不抢前台，同一只应用 8 秒内只拉一次。

### 1.58.12 追加：管理限额页放开修改时间

「冻结应用 → 使用限额 → 管理限额 · 独立 / 共享」不再只在 21:00–21:59 可改：`DailyQuotaData.EDIT_WINDOW=false`，`editable()` 恒真、`requireEdit()` 不再抛，页面顶部改成「随时可修改 · 当天已用时间保留」，启用开关、添加／合并／拆分／移除都不再置灰。真机 19:59（旧窗口之外）实测：页面不再是「设置已锁定 · 下次开放 10/30 21:00」，点「＋ 添加限额格子」直接弹出名称／分钟／选择应用的对话框，取消后没有写入任何分组。代价是额度可以在用爆之后直接调大——这是放开编辑窗口换来的，想收回把 `EDIT_WINDOW` 改回 true。

### 1.58.12 追加：删掉“合并／拆分”，共享＝一个格子勾多个应用

用户反馈「设置共享格子不够方便」，要求把管理限额里的独立／共享那套功能删掉。`DailyQuotaActivity` 移除了「合并为共享格子」和「拆分为独立格子」两个入口及 `merge()`／`split()` 实现；格子成员一律在「修改应用和时长 → 选择应用」里勾选，勾一个就是单独额度，勾多个就是共用一份，默认名从「共享限额」改成「共用额度」。页面文案同步：「独立限额分别计时，共享限额合计多个应用」改成「一个格子放一个应用，就是它单独的一份额度；放多个应用，就是它们共用同一份额度」；冻结页入口从「管理限额 · 独立 / 共享 ›」改成「管理限额 ›」。数据模型不变：多成员格子仍然是同一个 `id` 下多个 `apps`，历史共享格照常计时和冻结；只是不再提供一键合并/拆分。

### 1.58.12 方案 A：额度改成“一行一个格子”，旧全天额度并进来

- 冻结页「使用限额」区不再按应用列额度，而是**一行一个额度（格子）**：图标 + 名称 + 「已用 x / y 分钟 · 剩余 z 分钟」+ 条。点一行 → 新建/修改额度对话框（名称、每天分钟数、勾选成员）；长按 → 菜单（修改 / 并到另一个额度 / 删除）。勾一个成员就是单独额度，勾多个就是共用一份，不需要再“合并”。
- 旧「全天限时」（`AppUsageQuota`，一只应用一份、天生不能共享）在进程启动时并进每日限额：`DailyQuotaStore.migrateLegacy` 把每只应用转成一个单成员格子（分钟数照搬，今天已用时间用 `AppUsageQuota.used` 结算后写进账本），然后清空旧表并置 `enabled=true`。只在有使用情况权限时迁移（否则今天的用量会归零），迁移前把旧的 `config/usage` 与 `limits` 分别留在 `afs_daily_quota/config_before_migration`、`usage_before_migration`、`afs_usage_quota/limits_before_migration`，便于回滚。
- 数据模型不变：一个格子＝`{id,name,minutes,apps[]}`，用量仍按包名列。所以合并只是把成员挪进目标格子（`DailyQuotaData.mergeInto`，分钟取两者较小值），今天已用自动累加；删除（`DailyQuotaData.without`）不动账本。
- 时段卡片里同样用这张额度卡：只列“在这个时段里有成员”的格子，没有额度的应用不再单独列行。
- 管理限额页保留独立入口（启用开关、使用情况权限、添加/编辑/删除），但没有任何合并/拆分按钮。

### 1.58.12 追加：成员图标全部展示、单独/共享二选一、新建额度进二级菜单

- 额度卡的成员图标改成自绘 `MemberIcons`：20dp、按可用宽度自动换行，**把每一只成员都画出来**，不再截断成「+N」；8 个成员的共享格子也是一行排满。卡片布局改为「名称 → 成员图标行 → 已用/剩余 → 进度条」。
- 新建/修改额度的对话框顶部加了「单独 / 共享」二选一：单独只允许挑一只应用（单选列表），共享可以勾多只（多选列表），切换模式会提示对应说明，保存时再次校验“单独额度只能放一只应用”。
- 冻结页「使用限额」右上角新增 ⋯ 二级菜单（`quotaAddMenu`）：新建单独额度 / 新建共享额度 / 管理额度，每行是彩色图标 + 标题 + 副标题 + 箭头，不再是纯文字列表；页面上不再直接摆“＋ 新建额度”按钮。

### 1.58.12 追加：额度里的应用可拖拽迁移，共享格子标题固定

- 成员图标从“画在一张位图上”改成真正的子 View（`MemberStrip` 流式布局，22dp 自动换行）：每枚图标都能单独长按发起拖拽，payload 与冻结页原有的应用拖拽一致（`freeze-app` + 包名）。
- 额度卡自己就是拖放目标：拖进另一张卡 = 从原格子摘掉、加进目标格子，被搬空的格子自动删除（`DailyQuotaData.moveInto`，纯数据，返回 1/0/-1 区分迁移/已在格内/目标不存在）；拖进同一个格子只提示“已经在这个额度里”。卡片在悬停时高亮。
- 多成员额度卡的标题固定写「共享格子」，不再拿某只成员应用的名字当标题；单成员额度仍然显示应用名。名称字段仍可在编辑对话框里改，长按菜单标题里也仍显示原名。

### 1.58.12 追加：成员图标放大到 30dp

成员图标从 22dp 放大到 **30dp**（间距 6dp，圆角 8dp），八只成员仍然一行排满；长按拖拽的落点也跟着变大，误触明显减少。再大就会把 8 只成员挤到两行（卡片可用宽约 1020px @560dpi）。

### 1.58.12 追加：应用库分「冻结时段 / 时间限额」两页，拖拽时自动切页

- 底部应用库从一张列表复制成两页（`libraryTab`）：**冻结时段**页按原有口径显示每只应用的时段状态（可使用 / 待安排 / 时段冻结 / 已冻结），**时间限额**页显示额度状态（未限额 / `N 分钟/日` / `共享格子 · N 分钟/日`）。
- 两页共用同一份应用清单与同一套拖拽载荷，任意页都能当拖拽源：拖到时段卡片＝进时段，拖到额度卡＝加进该额度，拖回应用库＝回库。
- 拖拽中悬停另一页约 0.35 秒会自动切过去（`hoverTab`），手指不用抬起；切页只刷新每块瓦片的说明文字，不重建列表，所以正在进行的拖拽不会被打断。
- 页签样式与额度的单独/共享一致：选中蓝底白字、未选中浅灰底灰字。

### 1.58.12 追加：两页各只列自己的应用

- **冻结时段页**：只列「待安排」的应用（不在任何冻结时段里的），已进时段的应用不再出现——要把它挪走，直接在时段卡片里拖。
- **时间限额页**：只列还能设额度的应用（`DailyQuotaStore.group(pkg)==null`），已经有额度的不再出现——它们的图标就在额度卡里，直接拖即可迁移。
- 页头数量跟着过滤结果走（真机：73 → 冻结页 47、限额页 62）。切页时 `renderLibrary` 重铺瓦片（列表短了，原本的懒加载游标也得按新列表重算），拖拽本身是系统级 drag，不因重铺中断。

### 1.58.12 追加：额度修改权限改成每晚 22:00–23:00 自动开放

- 额度配置（新建／修改／合并／拖拽迁移／删除）的“修改权限”不再随时可用，也不再需要手动开关：`DailyQuotaData.EDIT_WINDOW=true`、`WINDOW_HOUR=22`，每天 **22:00–23:00 自动开放**，其余时间锁定；`requireEdit` 的提示同步为「每日限额已锁定，仅每天22:00–23:00可修改」，管理页显示「设置已锁定 · 下次开放 MM-dd 22:00」。
- 冻结页在锁定时给出明确提示：⋯ 菜单里的新建、以及长按菜单的合并/删除、图标拖拽迁移，都会弹「每日限额只在 22:00–23:00 可改」，不弹对话框、不写数据。
- 撤掉上一版临时加的「使用情况访问权限已关闭 · 去开启」横幅——权限状态不再由界面催促。

### 1.58.12 追加：关键应用名单改成带图标的可选列表

「冻结应用 → 冻结设置 → 关键应用名单」不再是干巴巴一列勾选框：每行是 30dp 应用图标 + 名字 + 一行状态说明（`00:00 — 21:00 23:00 — 次日 00:00`、`全天 · 共享格子 60 分钟/日 · 每日限额用尽` 之类），右侧勾选框；顶部有搜索框（名字或包名都能搜）与「已选 N / 总数」计数，底部有「全选当前」「清空」。保存逻辑不变：新勾选的关键应用若还没有规则，会补一条全天规则，然后统一 `RuleStore.setKeyApps` + `rebuild()` + `applyRules()`。
