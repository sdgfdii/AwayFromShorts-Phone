# 卡管理、热爱奖励与周期总结

版本：1.53.0 / 2167。入口：底栏守卫 → 功能 → 卡管理。

## 确认的产品规则

- 六类卡统一设置：热爱、记忆、刷题、目标、禁忌、总结。原目标管理入口替换为卡管理；记忆工具、刷题目标及题库设置迁入对应分类。实际记忆和刷题仍在各自学习页面进行。
- 热爱卡在打卡页上滑完成。所有热爱卡合计每天最多领取一次奖励，每次奖励为 1–60 分钟；两项上限写在模型中，界面不能调大。删除、恢复、新建卡片、重复上滑不会重新取得当天名额。
- 未使用余额永久累计。守卫只在存在可减免的定时冻结时自动安排抵扣；每段不超过 60 分钟，并在已知时段切换或学习检查边界前结束。学习联动与禁忌惩罚不会被奖励绕过；如果资格提前消失，剩余预留额度退回余额。时间是全局实际时间，不按同时放行的应用数量重复收费。
- 周报更名总结卡，支持每天、每周、每月和 1–365 天自定义周期。自定义周期可指定首日；默认仍为自然周。
- 总结在周期最后一天出现，20:00 起未完成则参与学习联动。跨周期仍保留最早待办，补完后才推进到下一周期；有多期逾期时逐期完成。不能靠修改周期删除已经到来的待办。
- 从打卡历史打开总结，可填写收获与计划，点击完成后保存并返回打卡页播放上滑。查看或切换总结不会自动完成；20:00、23:59 或跨日也不会自动完成。
- 已完成总结和文字可以在打卡历史查看。旧版当周已确认周报迁移为已完成总结；不追补新功能启用前没有追踪的旧周期。

## 实现与存储

- `CardData`：纯 Java 奖励账本、每日领取上限、按时间预留/退回的减免记录。
- `CycleSummary`：按日历计算周期、到期时刻与逾期游标。用日历日期而非固定 24 小时时差处理周期，覆盖闰年和夏令时。
- `CardStore`：`AtomicFile` 存储在应用私有 `cards-v1.json`，先写盘再发布缓存；失败不确认奖励或总结。普通目标、记忆库、题库和冻结时段的数据文件不迁移、不重置。
- `Guard`：预留奖励、应用冻结与原因显示共用带奖励的判定；定时边界包含奖励到期。设置锁仍按原冻结规则，不因奖励放行而解锁修改。
- `CardManagementActivity`：统一设置入口；沿用当前主题、瑞士排版、原生 Java 与多 Activity，无新增运行时依赖。
- `HistoryActivity`：任意周期统计、总结文字和完成记录；完成事件携带周期标识，避免把新一期卡片当成刚完成的上一期。

新卡管理文件仅存在本机。旧的记忆备份、学习台账同步分别覆盖原模块，当前不包含新增奖励与总结文件。
