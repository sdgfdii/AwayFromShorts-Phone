# 记忆卡融合方案（墨墨参考，M1 已实现）

日期：2026-11-03。适用：AwayFromShorts 手机端。调查证据见 [EVIDENCE.md](EVIDENCE.md)。状态：用户已于2026-11-03批准首批四组派生功能，M1–M5已实现、独立静态评审及模拟器验证；具体结果见 HANDOFF.md。未迁移数据。本方案与根目录的 R2 插件设计分开保存，不覆盖其批准记录。

## 1. 推荐范围

首批只增加四组可派生功能：复习时间预览、今日负荷分解、难记卡筛选、统计时间粒度和稳定性分布。全部沿用已有卡片和日志；不新增数据库字段、依赖、网络服务、自动任务或词库。

- 保持原有上下滑/点击/输入题语义，只有认识与忘了两档；不恢复已被移除的模糊、费力、轻松按钮。
- 保持 FSRS-6、目标记忆率、最大间隔和本地零点开放规则；不将墨墨未知算法当作已还原算法。
- 保持每张卡在本日闪卡中每天一次；忘记的卡仍进入现有错题/重学排程，不暗中追加今日队列。
- 普通打卡与记忆卡的记录和排程继续分开。现有“完成记忆目标后通知打卡页展示”的明确联动保留；统计、筛选、预览不调用该联动，不增加打卡数或罚时。
- 所有学科可用；不把模块改成只支持英语的词汇软件。英语内容仍用现有制卡/导入工具准备。

## 2. 用户会看到什么

### 复习卡：可解释的时间反馈

沿用现有闪卡布局与手势，在既有卡片辅助区显示“认识后下次复习：…”与“忘了后重学：…”。题目、答案和图片遮挡流程保持现状；已评分卡展示实际落盘的到期时间，不再预演第二次评分。显示“今天约10分钟后”或“日期”而非保证记忆时长。

预演必须复用真实排程与零点归整，使用独立 State。不得调用 `rate` 或初始化当日队列来取预览；跨日/修改卡片后使用新的快照重算。

### 今日进度：把负荷说清楚

现有总进度旁补充本日待复习、待新学、已处理和当前设置可容纳的数量；区分“本日入队”与“卡库全部积压”。保持用户已经设置的总数量和新学上限，不改成另一套额度。

日志评分次数与去重卡片数分开标注；“处理了遗忘卡”不等于“有效目标完成”。已有卡库和当日队列决定计数，不另建计数器。

### 卡片管理：更快找到难记卡

在现有卡片/错题页面提供“全部、今日队列、难记”筛选与排序。原错题 = 曾经遗忘（lapses>0）保留；新增“难记”定义为本应用自己的 `lapses>=3`，并在筛选说明中公开，不能声称复刻墨墨的顽固度算法。排序按遗忘次数降序，再按到期时间、ID 稳定排序。显示难记数量但不自动暂停、删除或降低学习目标。

“今日队列”只读已存在的 session；没开始学习时显示未生成，不能因为浏览筛选页而抽卡。切换筛选不写卡库，不触发评分。

### 记忆统计：日／周／月与稳定性

复习统计增加粒度切换（日：近30个自然日；周：近12个自然周；月：近12个自然月，含当前周期），并可按现有学科过滤。按本地 Calendar 边界分桶，禁止拿30天当一个月或拿固定毫秒天跨夏令时分周。

补充“FSRS稳定性分布”：仅针对当前在用且进入 REVIEW 的卡，互斥区间 <10、10–29、30–59、60–89、≥90天；新卡、学习/重学中的卡单列，不混分母。不将稳定性、目标记忆率、真实日志留存率混称为同一个指标。已有7天到期预测和基于历史日志的留存曲线保留；样本不足显示不足，不能画出伪造的个人曲线。

## 3. 真实链路与模块归属

| 关键文件/类 | 当前职责 | 本次边界 |
| --- | --- | --- |
| MemoryActivity.grade/revealCard | 唯一评分、答案显示、提交保护、既有目标完成通知 | 仅接入预览、展示、筛选入口；不新增评分路径或改变手势 |
| MemoryStore.rateFlashcard/rate/save | 缓存、AtomicFile持久化、现有失效通知 | 写入链不变；新增真正只读快照用于统计 |
| MemoryData.rateFlashcard/applyRating | 当日队列校验、FSRS状态、日志、学科计划credit | 抽取统一的只读下次状态计算，写入与预览共用；不改变公式 |
| MemoryScheduler.next | FSRS-6数学及分钟/按天间隔 | 不修改算法和上游权重 |
| MemoryFlashcards.session/next/complete | 当日固定队列、风险排序、新学补位、seen | 不重排旧队列；负荷与今日筛选只读已有ids/seen |
| MemoryStats | 摘要、历史与预测的纯计算 | 扩展周期桶和稳定性统计，按学科过滤 |
| MemoryChartView | 原生图表 | 复用现有绘制，增加可读标签/无数据语义，非持续刷新 |
| 拟增 MemoryCardQuery | 派生卡片筛选、稳定排序、分页ID | 纯Java，不写入、无Android Context/计时器 |

调查发现：`MemoryStore.snapshot()` 会执行 `plans()`；`flashSnapshot()` 也可能生成 session 并保存。它们不能被当作无副作用的统计读取接口。首批须新增只读快照，不为统计初始化计划，也不借本次重构其他存储入口。

## 4. 已实现的最小内部契约

沿用 Java8 / 原生 View / Android24，无新增插件协议或外部数据接口。

| 签名 | 调用方/用途 | 不变量 |
| --- | --- | --- |
| `static synchronized MemoryData MemoryStore.readOnlySnapshot(Context c)` | 后台读取供统计/筛选，返回独立数据副本 | 不调用plans/session/save；不修改revision/普通打卡/规则 |
| `MemoryScheduler.State MemoryData.previewRating(String id,int rating,long now)` | UI展示与applyRating共享统一的下一状态计算 | 不改卡片、日志或计划；归零点与实际提交一致；无效ID/评分明确报错 |
| `MemoryFlashcards.Load MemoryFlashcards.inspectLoad(MemoryData m,long now)` | 展示已有今日session的新卡/旧卡/seen与卡库积压 | Load是只读值；不调用会写session/day/root的访问器 |
| `MemoryStats.PeriodSeries MemoryStats.periods(MemoryData m,long now,Period unit,int count,Set<String> decks)` | 日/周/月图表 | 本地自然日历桶，空桶存在，未来日志与回收站排除；空Set含义显式定义为全部在用学科 |
| `int[] MemoryStats.stabilityBands(MemoryData m,Set<String> decks)` | 稳定性图表 | 只统计在用REVIEW，互斥5桶；按真实stability分桶 |
| `List<String> MemoryCardQuery.page(MemoryData m,Filter filter,Set<String> decks,long now,int offset,int limit)` | 卡管理筛选，首版50条/页 | 返回ID，不复制图片/正文，不评分；总排序稳定，回收站排除 |

例：`previewRating(cardId,3,now).due` 只预演认识；真正上滑仍调用原 `MemoryStore.rateFlashcard(...)`。提交使用实际时间重算，若跨日/卡片变化，允许预览更新，不能提交旧预演状态。

例：`periods(snapshot,now,Period.MONTH,12,selectedDecks)` 返回自然月标签、评分次数、认识次数和去重卡数；界面明确指标，不把新学重复算成多张卡。

## 5. 性能与兼容

单次进入统计/筛选只取得一份后台快照并在该页复用。不得主线程扫描全库或每个组件复制完整JSON。使用页面generation丢弃离开后的任务结果；最多一个在途计算，不建后台轮询和持续动画。卡片列表按ID分页，图片复用现有按需解码。

不迁移 `memory-v1.json`，不新增持久化配置。周期/筛选在页面实例保存，返回时保留位置；后续要跨重启记忆设置需另列字段。老日志缺字段保持老含义，不回填“学习耗时”、音标或例句。英语扩展内容今后通过用户授权内容导入，不随本批复制第三方词库/音频。

## 6. 明确后续项

- 增加“模糊”或改变遗忘/认识手势：会改变评分与FSRS映射，需单独批准。
- 同一天遗忘卡重复巩固：与当前“一卡一天一次”冲突，需独立队列、去重/目标计数与备份设计，不在首批加入。
- 暂停/标熟/不想背：会改变卡片状态、队列与目标分母，需新字段、备份与恢复约束。
- 音频播放、英美音、音标/例句/词形字段：需明确内容来源和导入字段，不能把APK词库当可分发数据。
- 自动个性化训练参数：现有FSRS未开启优化器；REA没有还原墨墨算法，不在本批声称可复制。

用户已批准本批四组功能与“难记=lapses≥3”的口径。实现和验证证据见 [HANDOFF.md](HANDOFF.md)，后续项仍不属于本批范围。
