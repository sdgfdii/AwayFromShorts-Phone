# 打卡页（CheckinActivity）

> 一屏一张竖卡，**往上推**就记一笔，**左右推**换目标。

它在守卫 App 里，和"没打完就继续冻"是同一件事的两面 ——
所以不再单独装一个 APK（原来那个 `com.afs.checkin` 已经并进来了）：
一个图标、一份数据、一个进程。

## 为什么是一张竖卡，不是一列横条

原来的打卡页是一列横条，选中的那条往上滑。功能没问题，但读起来是"表单"，
而且一屏只能看到三四个目标的全貌以外的信息。

改成一屏一卡之后：

- **一张卡就是一屏**，目标名、进度、要记多少，全都不用扫；
- 三种手势方向分明，闭着眼也不会打错：上 = 提交，左右 = 换一个看看；
- 卡后面还压着下一张（缩放 0.94 + 下移），上推时会跟着浮上来 ——
  "打完还有下一个"这件事是看得见的。

卡中间那一圈进度环不是装饰：竖卡中间那块地，一条 6dp 的细进度条根本填不住，
会显得空荡荡；环既是视觉重心，也把"我到哪儿了"说清楚了。

## 手势

| 动作 | 结果 |
| --- | --- |
| **上推** | 打卡当前目标。没推够松手回弹，不会误打；推过阈值有震动反馈 |
| **左推** | 下一个目标（卡从右边进来） |
| **右推** | 上一个目标（卡从左边进来） |
| **长按卡片** | 手动填这一笔的数量（默认建议量） |
| 右上「上传」 | 立刻把台账推到云端（平时打卡落盘就会自动推，这颗用来确认） |
| 右上「禁忌」 | 禁忌卡设置与认领 |
| 长按状态行 | 换 token（推云端用，只授 gist 权限） |

阈值不是拍脑袋定的：竖推要 26% 的舞台高度（夹在 120dp~230dp），
横推要 28% 的宽度。手指移动超过 12dp 才判定方向 —— 否则"点一下"会被手势吞掉。

建议量用的是学习台 `suggestOf()` 同一套算法：
`剩余量 / (剩余天数 + 1)`，≥1 向上取整，否则保留一位小数。
两边算法不一致的话，同一天在不同地方打卡会得到不同结果，看着像 bug。

## 手机自己就是学习台（没有电脑的人）

上面那条"绕 Gist 回 PC"的链路，前提是你有一台常开的电脑。**没有电脑的话，
整条链路都不需要** —— 手机本地就有完整的学习台（`StudyStore`，落盘在
`filesDir/study.json`）：

- 右上「**管理**」：新建 / 编辑 / 删除目标（名字、单位、总量、截止日），
  顺手设「联动冻结时段」（默认 22:00–23:00）；
- 上推打卡**直接落盘**，闸门下一拍就用新数据重判，全程不联网；
- 闸门读的是本机算出来的快照，和 Gist 那份 `study-gate.json` 同构，
  判定逻辑一行没改 —— 没有"另一套规则"的隐患。

**从老链路过来的数据不会丢**：第一次进 App 时会把 Gist 上 `study-gate.json`
里的目标导入成本机数据（目标 id 保持 `goal-*` 前缀，本机新建的是 `g*`）。
导入是**一次性**的 —— 之后本机就是源数据，再导会把你在手机上改的东西冲掉。

导入格式升过两版，都会自动自愈（`StudyGate.init` 里）：

| 版本 | 问题 | 自愈方式 |
| --- | --- | --- |
| v1 | `done` 里含今天已打的量，导入当天重复要求打卡 | 清库重导，带 `hitAtImport` 快照 |
| v2 | 用的是缓存的旧快照；清库/删错目标后无法恢复 | 清库 → **先拉最新 gate** → 再导 |

判据不是"导入过没有"的布尔标记（会被清库带走），而是目标 id 前缀：
库里还有 `goal-*`（PC 来的）或干脆是空的 → 自愈；全是 `g*`（手建的）→ 不碰。

### 哪条链路在跑？

状态行末尾就是标记：「还有 N 个待打卡 · **本机**」= 手机自己说了算；
没有后缀 = 还在走 PC 那条老链路。判定开关是 `StudyStore.hasGoals()` ——
只要本地有目标，Gist 上的闸门数据就不再参与判定。

## 为什么不在网页上打卡

学习台的页面只能在 WorkBuddy 宿主的 iframe 里跑：

- `inject.js` 一检测到自己是顶层窗口（`window.self === window.top`）就
  `document.write` 一段"安全限制"再 `window.stop()`，页面直接变空白；
- 数据层 `window.__SMART_PAGE__.database` 靠 `postMessage` 跟父页面通信，
  真正发请求的身份在宿主那边。

所以任何独立 App 都**拿不到写学习台的凭据**，这条路走不通。

## 那数据怎么回去

手机就是学习台：打卡直接写本机 `study.json`，闸门当场重算，不用绕网络。

```
打卡页 ──上推──▶ StudyStore（study.json）
                     │
                     ├─▶ 立刻：StudyGate.invalidate ──▶ Guard.apply（当场解冻）
                     └─▶ 后台：Hub 打脏标记 ──▶ 推 checkin-ledger.json（Gist 中心）
                                                        │
                                     PC（check_study.py）读台账
                                                        ▼
                                                PC 面板看板
```

`Hub` 在打卡落盘那一刻就开线程推（脏标记优先，不看 10 分钟节流），
所以"打完 → 云端有新版本"是秒级的。

### 手动上传（确定性确认）

- 打卡页右上「上传」：推完提示 `已上传 HH:mm · rev N`
- 历史页「同步」卡：同样的 `Hub.pushNowSync`，另外常驻显示
  「上次上传：MM-dd HH:mm · rev N」

### 老队列链路已删

`CheckinStore` + `CheckinSync` + `checkin-queue.json`（手机排队 → PC 代记账）
在 v1.31.0 整体删除。现在只有一份数据源：`StudyStore` → `Hub` 台账。
Gist 上残留的 `checkin-queue.json` 是历史文件，两端都不再读写。

## 离线

打卡永远能落盘（本机文件写成功就算数），云端推送失败不影响闸门和页面。
失败只影响 PC 端看到的数据新鲜度 —— 下次打开 App、或点一下「上传」就重试。

## 构建

```bash
cd dpc
echo "<github-token>" > token.local   # 只放本地，不入库
bash build.sh                          # 产物 ../afs-guard.apk（和守卫同一个包）
adb install -r ../afs-guard.apk
```

没有 `token.local` 也能构建，只是首次要长按标题手动粘 token。
`token.local` 和生成的 `BuildConfig.java` 都在 `.gitignore` 里 ——
APK 里能 grep 到 token，所以产物**不进公开仓库**。

## 已知限制

- **读 Gist 的 raw 有 CDN 缓存**（约 1 分钟）。另一台设备要等一会儿才看得到新数据；
  判断实际状态看 `adb logcat -s AFS | grep -E "checkin|hub"`。
- PC 一直不开机时台账推不上去，但手机端完全正常（本机就是权威数据源）。
- PC 面板的统计以台账为准，所以两端短时间不一致是正常的（差一次推送往返）。
